### Semgrep Community Edition — completed

- Target: Router `b26629b`, 110 Git-tracked files.
- Rulesets: `p/typescript`, `p/nodejs`, and `p/secrets`.
- Result: 111 rules ran; one low-confidence secret-pattern match.
- Triage: **false positive**. The matched catalog value is the ordinary UI text
  `requires login`; it is not an OAuth credential or secret.
- Decision: do not exclude the full service catalog merely to make the count
  zero. That would hide future real credentials in a high-value generated file.
- Artifact: `audit/artifacts/semgrep-b26629b.json` (re-run 2026-08-12, Semgrep
  CE 1.139.0; 111 rules on 111 targets, same single finding and same triage).
- Caveat for the auditor: the scan reports one partial-parse error at
  `src/utils/redact.ts:41`. The file embeds a literal NUL byte as an HMAC domain
  separator, which the parser rejects. The byte is intentional, but static rules
  did not fully cover that file — review it manually.

Reproduce from an isolated checkout:

```bash

  --config p/typescript \
  --config p/nodejs \
  --config p/secrets \
  --json \
  --output audit/artifacts/semgrep-b26629b.json \
  .
```

## Pending automated passes

### Almanax

Connect the Almanax GitHub App once, select `mpprouter/rozo-mpprouter`, and pin
the baseline scan to `b26629b`. Configure these project invariants before the
scan:

- A refund must use the payer and asset proven by the original Stellar payment.
- One inbound payment can reserve and confirm at most one full refund.
- A refund is not confirmed until the exact signed envelope succeeds on-chain.
- Automatic signing is strictly below USD 100; runtime configuration cannot
  raise the threshold.
- Channel settlement must never exceed the funded deposit or accept a stale
  voucher as a balance increase.
- Public routes must not expose signing keys, admin capabilities, or raw signed
  envelopes.

Enable automatic PR reviews after the baseline scan. Export the result to PDF
and place the shareable copy or URL under
`audit/almanax/`. Almanax documents GitHub-based PR reviews and
report export; no repository credential should be committed here.

### Semgrep AppSec Platform + Assistant

The repository already includes a token-free CE workflow. To add AI triage and
fix suggestions, connect the repository to Semgrep AppSec Platform and store its
generated `SEMGREP_APP_TOKEN` only as a GitHub Actions secret. Then replace the
CE scan command with `semgrep ci`. Keep PR, main-branch, scheduled, and manual
triggers enabled.

## Remediation gate before the paid audit starts

1. Triage every high or critical result for runtime reachability.
2. Fix confirmed findings on a dedicated branch; do not rewrite the baseline.
3. Run type-checking, tests, Worker dry-run bundling, Semgrep, and dependency
   audits again.
4. Update the audit firm's scope sheet with the final Router SHA.
5. Preserve both the original report and the remediation re-scan so reviewers
   can follow the evidence trail.
